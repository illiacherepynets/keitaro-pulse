# Keitaro · Pulse — локальний дашборд

Візуальна аналітика трафіку Keitaro по днях: який **сайт/кампанія** приносить кліки й конверсії, який **бренд/офер** конвертить, розподіл по **гео** та **ОС**. Підтримує **кілька команд** (Keitaro-інстансів) — спільний звіт і по кожній окремо. Усе — локально на ПК, без сервера.

## Команди (кілька Keitaro-інстансів)

Ключі команд **не зберігаються в коді** (щоб їх можна було безпечно тримати в публічному репозиторії). Джерело конфігу:

- **Локально** — файл `teams.local.json` поруч із `fetch.mjs` (він у `.gitignore`, не комітиться):
  ```json
  {
    "teams": [
      { "name": "Команда 1", "url": "http://SERVER_IP_1", "key": "API_KEY_1" },
      { "name": "Команда 2", "url": "http://SERVER_IP_2", "key": "API_KEY_2" }
    ]
  }
  ```
  Додати команду = дописати обʼєкт (`url` — БЕЗ `/admin/`, лише `http://IP` або домен).
- **Онлайн (GitHub Actions)** — той самий JSON у секреті `KT_TEAMS`. Див. розділ «Онлайн».

**Назви команд** задаються в `fetch.mjs` — константа `TEAM_NAMES` на початку
файлу. Порядок у ній = порядок команд у `KT_TEAMS`. Тримаємо їх у коді, а не в
секреті: перейменування — один коміт, без перевводу URL та API-ключів, де одна
помилка ламає всю збірку. Порожній рядок або відсутній елемент → лишається
назва з `KT_TEAMS`.

Після `node fetch.mjs` у шапці зʼявляється перемикач **Всі команди / Folders /
Drop domains …**:
- **Всі команди** — спільний звіт (усе сумується). У таблиці сайтів кожен рядок
  має чіп команди (`Folders`, `Drop`, `Monobrands` …; повна назва — у tooltip).
- **Конкретна команда** — увесь дашборд показує лише її дані.

Перемикач команди комбінується з усім: фільтром сайту/бренду, періодом, днем, позиціями/сторінками. Deep-link: `dashboard.html#team:1`.

## Як користуватись

### Варіант 1 — подвійний клік
Запусти **`Старт.bat`**. Він оновить дані з Keitaro і сам відкриє дашборд у браузері.

### Варіант 2 — через Claude Code / термінал
```
node fetch.mjs
```
Потім відкрий `dashboard.html` подвійним кліком.

> `fetch.mjs` витягує **всю доступну історію** з Keitaro (`report/build`) і вшиває її прямо в `dashboard.html`. Файл самодостатній — працює офлайн, нічого встановлювати не треба (лише Node.js для оновлення даних).

## Що всередині дашборду

- **KPI** — кліки, конверсії, CR, ліди, продажі, дохід, кількість активних сайтів (+ зміна відносно попереднього такого ж періоду).
- **Трафік по днях** — графік кліків (площа) і конверсій (золота лінія). Клік по графіку → перехід у режим конкретного дня.
- **Перемикач періоду** — Весь період / 90 / 30 / 7 днів, або вибір конкретного дня.
- **Сайти / кампанії** — сортована таблиця: гео, кліки, конверсії, CR, ліди, продажі, дохід.
- **Бренди / офери** — те саме на рівні оферів (справжній бренд).
- **Сторінки (sub_id_3)** та **Позиції × бренди** — клік по сторінці зліва → праворуч видно, які бренди й на яких позиціях (sub_id_2) стояли саме на цій сторінці (клік по бренду в цій таблиці → фільтр на нього). Deep-link: `dashboard.html#page:non-aams`.
- **Сайти з конверсіями** — окремий фокус на тих, хто реально дає результат.
- **Гео**, **Мережі (префікс)**, **ОС** — розподіли.

## Фільтр (весь дашборд «про одну сутність»)

Панель фільтра у шапці:
- **Тип** — `Сайт` (кампанія) або `Бренд` (офер).
- **Режим** — `Частковий` (містить підрядок) або `Точний` (повний збіг назви).
- **Поле пошуку** — вводиш назву → усі панелі (KPI, графік, гео, таблиці, позиції, сторінки) перераховуються тільки по цій сутності.
- **Клік по будь-якому рядку** таблиці сайтів/брендів/конверсій → миттєвий точний фільтр на цю сутність.
- Хрестик на чіпі праворуч скидає фільтр.

Коли фільтруєш **бренд** — таблиця «Сайти» показує, на яких кампаніях він крутився, а панелі **Позиції/Сторінки** — з яких сторінок ішли кліки і на яких позиціях бренд стояв (весь період).

Фільтр можна закинути прямо в URL для швидкого доступу: `dashboard.html#brand:winshark` або `dashboard.html#site:TNTN_IT`.

> Позиції/Сторінки та крос-звʼязок сайт↔бренд рахуються за **весь період** (не залежать від вибраного діапазону днів) — це структурні дані. KPI/графік/таблиці по кліках і конверсіях враховують і фільтр, і період.

## Звірка з Keitaro (важливо про цифри)

- **Дохід (підтв.)** = метрика `sale_revenue` — це те, що Keitaro показує як «Дохід (підтв.)» / «Прибуток (підтверджений)». Саме її треба порівнювати з UI Keitaro.
- **Дохід (усього)** = метрика `revenue` (ліди + сейли, ще не підтверджені) — завжди більший за підтверджений. Не плутай його з «підтвердженим».
- **Завершені дні:** за замовчуванням дашборд НЕ рахує неповний поточний день (`INCLUDE_TODAY = false`), щоб збігатися з пресетом Keitaro «останні N днів». Тому «30 дн» = останні 30 повних днів.
- Невелика різниця в **кліках** (≈0.5–1%) можлива, бо пресет Keitaro «останні 30 днів» може включати кілька годин сьогодні, а також через таймзону звіту. Якщо в твоєму Keitaro інша таймзона — постав таку саму в `TZ`.

## Онлайн (GitHub Pages, автозапуск щоранку о 10:00)

Дашборд може оновлюватися сам у хмарі й бути доступним за приватним посиланням. Дані шифруються паролем (AES-GCM) прямо в момент білду, тож у HTML немає нічого читабельного без пароля — тому хостити можна навіть на **безкоштовному публічному** GitHub Pages.

**Разове налаштування:**
1. Створи **новий репозиторій** на GitHub і залий у нього **вміст папки `dashboard/`** (саме її, не весь проєкт — щоб не потрапили CSV/xlsx з іншими даними). `teams.local.json` не заллється (він у `.gitignore`).
2. У репозиторії → **Settings → Secrets and variables → Actions → New repository secret**, додай два секрети:
   - `KT_TEAMS` — JSON зі списком команд (той самий вміст, що в `teams.local.json`, поле `teams` або просто масив).
   - `KT_PASSWORD` — пароль, яким шифрується звіт (його вводитимеш на сторінці).
3. **Settings → Pages → Build and deployment → Source = GitHub Actions**.
4. **Actions →** обери воркфлоу *Build & Deploy Keitaro Pulse* → **Run workflow** (перший запуск вручну). Далі він сам працюватиме щодня.

Готове посилання зʼявиться в **Settings → Pages** (вигляду `https://<логін>.github.io/<репо>/`). Відкриваєш → вводиш пароль → бачиш свіжий звіт. Пароль тримається лише в памʼяті вкладки (`sessionStorage`).

- **Розклад:** `.github/workflows/build.yml`, `cron: "0 7 * * *"` = 10:00 за Києвом улітку (09:00 узимку — через перехід на зимовий час; за потреби зміни на `0 8 * * *`). GitHub інколи стартує на кілька хвилин пізніше — це нормально.
- Кнопка **Run workflow** у вкладці Actions запускає оновлення будь-коли вручну.

## Налаштування

Зверху `fetch.mjs` (не секретне):
- `TZ` — таймзона; має збігатися з таймзоною звіту в Keitaro.
- `DAYS_BACK` — `null` = вся історія; або число днів (напр. `90`).
- `SEARCH_FROM` — найраніша дата, з якої шукати історію.
- `INCLUDE_TODAY` — `false` (реком.) рахує лише завершені дні; `true` додає неповний сьогоднішній.

## Файли
| Файл | Призначення |
|------|-------------|
| `fetch.mjs` | тягне дані з Keitaro → генерує дашборд (plaintext локально / зашифрований онлайн) |
| `template.html` | дизайн/логіка дашборду + екран входу (редагується окремо) |
| `dashboard.html` | **згенерований** локальний дашборд — його й відкриваєш (у `.gitignore`) |
| `teams.local.json` | ключі команд для локального запуску (**секрет**, у `.gitignore`) |
| `Старт.bat` | оновити дані + відкрити дашборд (локально) |
| `.github/workflows/build.yml` | автозапуск щоранку + деплой на GitHub Pages |

## Змінні оточення (для CI / ручного запуску)
| Змінна | Призначення |
|--------|-------------|
| `KT_TEAMS` | JSON зі списком команд (замість `teams.local.json`) |
| `KT_PASSWORD` | пароль для шифрування; якщо не заданий — дані вшиваються відкрито (локальний режим) |
| `KT_OUT` | шлях виводу HTML (напр. `public/index.html`); типово `dashboard.html` |
